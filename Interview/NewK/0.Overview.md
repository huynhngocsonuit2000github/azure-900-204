# Stage 0 – Foundation Check (1–2 weeks)

Goal: Make sure your .NET + general knowledge is solid enough to go deep.

- OOP, SOLID, clean architecture, DDD basics (entities, aggregates, bounded context).
- HTTP, REST, JSON, JWT, OAuth2, OpenID Connect.
- SQL (joins, indexing, execution plans), basic data modelling (OLTP vs OLAP).

# Stage 1 – Advanced .NET 8/9 + Blazor (3–4 weeks)

## .NET 8/9

- Minimal APIs, endpoint filters, middleware pipeline.
- EF Core:

  - Tracking vs NoTracking, compiled queries.
  - Migrations in multi-env (dev/test/prod).
  - Transactions, concurrency, performance tuning.

- Advanced:
  - Background services (IHostedService).
  - Caching (MemoryCache, distributed cache).
  - Logging, structured logs (Serilog style).

## Blazor

- Component architecture, lifecycle, event callbacks.
- Forms + validation, EditForm, custom validators.
- State management: cascading values, DI, local storage.
- Authentication & authorization with tokens (integrate with Entra/B2C later).

Practice project

- Build a Blazor front-end + .NET 8 API Todo/Order app with:
  - Clean architecture (API + Application + Domain + Infrastructure).
  - EF Core with PostgreSQL/SQL Server.
  - JWT-based auth (later replace by Entra/B2C).

# Stage 2 – Microservices + Apache Pulsar (3–4 weeks)

Microservice design

- Monolith vs microservice – when to split.
- Synchronous vs asynchronous communication.
- Patterns: API Gateway, Circuit Breaker, Retry, Saga (orchestration vs choreography).
- Observability: correlation IDs, distributed tracing basics.

Apache Pulsar

- Concepts: tenant → namespace → topic → partition → subscription.
- Subscription types: Exclusive, Shared, Failover, Key_Shared.
- Exactly-once vs at-least-once semantics.
- Producer/Consumer patterns from .NET clients.
- Handling failures, dead-letter topics, message reprocessing.

Practice project

- Service A: Order API.
- Service B: Notification API.
- Use Pulsar topic orders for events.
- Implement:
  - OrderCreated event → Notification service consumes and sends fake email/SMS.
  - Retry & DLQ handling (log to DB).

# Stage 3 – Cloud Skills: AWS + Azure Identity (3–4 weeks)

## AWS (for “experience” level, not deep specialist)

Focus on:

- Core services: EC2, S3, RDS, Lambda.
- Networking: VPC, subnets, security groups.
- IAM: roles, policies, least privilege.
- API Gateway + Lambda: simple serverless microservice.
- CloudWatch: logs, metrics, alarms.
- Basic CI/CD with CodePipeline or GitHub Actions deploying to EC2/Lambda.

Practice

- Deploy a small .NET API to EC2 or Lambda + API Gateway.
- Add logs/metrics and explain how you’d debug issues.

## Azure Entra ID / B2C / External ID (deeper)

- Identity concepts:

  - OAuth2 flows (Auth Code with PKCE, Client Credentials).
  - OpenID Connect: ID token vs access token.
  - Scopes, consent, roles.

- Azure Entra ID:

  - Register apps, expose API permissions.
  - Validate tokens in .NET (JwtBearer).

- B2C / External ID:

  - Tenants, user flows vs custom policies (high level).
  - Frontend → redirect → token → call backend.
  - Multi-tenant / multi-app scenario.

- Practice, Modify your microservice app:
  - Use Azure Entra External ID/B2C for login.
  - Blazor gets access token, calls .NET API with Authorization: Bearer.
  - Backend validates roles/claims and protects certain endpoints.

# Stage 4 – Data Warehouse, SSIS, Power BI (3–4 weeks)

## Data Warehouse & ETL (SSIS)

- Concepts:

  - OLTP vs OLAP.
  - Fact table, dimension table, star/snowflake schema.
  - Slowly Changing Dimensions (SCD1, SCD2).

- SSIS:
  - Control Flow vs Data Flow.
  - Sources/destinations, Lookups, Derived Column, Merge Join, Conditional Split.
  - Incremental loads, CDC pattern, error handling, logging.
- Performance: batch size, indexing, partitioning basics.

## Power BI

- Modelling:

  - Relationships, star schema in Power BI model.
  - Calculated columns vs measures.

- DAX basics:

  - SUM, COUNTROWS, CALCULATE, FILTER, time-intelligence functions.

- Report design:
  - Slicers, bookmarks, drill-through, row-level security (RLS).

## Practice project

Make a mini sales data warehouse:

- FactSales, DimCustomer, DimDate, DimProduct in SQL Server.
- Build SSIS package that loads CSV/OLTP → DWH (full + incremental).
- Create a Power BI report for:
  - Sales by month, product, customer segment.
  - Add at least 3 measures with DAX.

# Stage 5 – Camunda BPM & Service Orchestration (2–3 weeks)

What to learn

- BPMN basics: start/end events, gateways, user tasks, service tasks, timers.
- Process vs microservice: when to use workflow engine instead of pure code.
- Camunda concepts:
  - Process definition, process instance.
  - External task worker vs REST calls.
  - How to correlate messages & variables.
- Error handling: retries, escalation, compensation.

Practice project

- Model an Order Fulfillment Process:
  - Steps: Validate Order → Reserve Stock → Take Payment → Notify Customer.
  - Implement two of these steps as .NET microservices (REST / worker).
  - Camunda orchestrates:
    - If payment fails → cancel stock reservation → mark order failed.
