# Core definition

There are some ways to expose the the Pod

| Component        | Accessible from?       | Purpose                |
| ---------------- | ---------------------- | ---------------------- |
| **Pod IP**       | only inside cluster    | internal communication |
| **NodePort**     | internet (bad)         | quick debugging        |
| **LoadBalancer** | internet               | expose app publicly    |
| **Ingress**      | internet + domain name | production traffic     |

- When you install the NGINX Ingress Controller, AKS creates ONE public IP. This is the entry point for your whole cluster.

- The way access to the Pod from the Internet

```sh
User Browser
    ↓
DNS Provider (api.myapp.com → 20.205.33.10)
    ↓
Public IP (Ingress Controller)
    ↓
Ingress Rules (domain/path matching)
    ↓
Service (stable internal endpoint)
    ↓
Pod(s) (your application)
```

- Ingress Controller = NGINX server running inside Kubernetes. That's it — same idea, just automated and containerized.

| Item                         | **NGINX on Linux**                         | **Ingress in Kubernetes**                                   |
| ---------------------------- | ------------------------------------------ | ----------------------------------------------------------- |
| **What it basically is**     | A reverse proxy server                     | A reverse proxy **configuration**                           |
| **Who does the real work?**  | NGINX process running on the server        | **Ingress Controller** (NGINX running inside AKS)           |
| **Where rules are defined?** | `nginx.conf` files                         | Ingress YAML files                                          |
| **How routing works?**       | NGINX reads nginx.conf → routes to backend | Ingress Controller reads Ingress YAML → routes to Services  |
| **One server / Many apps?**  | Needs many config files manually           | One Ingress Controller can route to many apps automatically |
| **Public IP**                | Server’s own IP                            | Azure Load Balancer IP attached to Ingress Controller       |
| **TLS / HTTPS**              | NGINX handles it with certificate files    | Ingress Controller handles TLS with Kubernetes Secrets      |
| **Scaling**                  | Manual                                     | Automatic inside AKS                                        |
| **Updates**                  | Must reload NGINX manually                 | Controller reloads automatically when YAML changes          |
| **Main purpose**             | Proxy traffic to backend apps              | Proxy traffic to Kubernetes Services → Pods                 |
